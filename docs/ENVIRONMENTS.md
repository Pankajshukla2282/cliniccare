# ClinicCare Microservice Environment Runbook

## Overview

ClinicCare is decomposed into **9 independent microservices** deployed across Kubernetes namespaces. Each microservice has its own Prisma schema, Docker image, and deployment manifest, all sharing a single PostgreSQL database with row-level isolation via `organizationId`.

## Supported Environments

| Microservice | Environment | Kubernetes Namespace | Database Schema |
|---|---|---|---|
| **auth** | `development` | `cliniccare-development` | `public` + auth tables |
| **auth** | `staging` | `cliniccare-staging` | shared staging DB |
| **auth** | `production` | `cliniccare-production` | dedicated prod DB |
| **clinical** | all envs | same as auth | shared across clinical services |
| **billing** | all envs | same as auth | shared across billing services |
| **product** | all envs | same as auth | shared across product services |
| **queue** | all envs | same as auth | shared across queue services |
| **lab** | all envs | same as auth | shared across lab services |
| **cms** | all envs | same as auth | shared across CMS services |
| **web** | all envs | separate ingress | reads from all services |

## Environment Isolation

- **Infrastructure**: Each environment uses isolated Kubernetes namespaces, secrets, and DNS
- **Database**: Production uses a dedicated PostgreSQL cluster; dev/staging share a pooled instance
- **Secrets**: JWT secrets, database URLs, and API keys are namespaced per environment
- **Tenants**: Tenant data is logically isolated via `organizationId`; physical isolation via separate DB schemas in production

## Microservice Deployments

Each microservice has its own:

- `Dockerfile` - Container build (ports: auth=3001, web=80, API=3000)
- `prisma/schema.prisma` - Service-specific Prisma schema
- `infrastructure/k8s/` - Kustomize overlays per environment
- `package.json` - `@cliniccare/*` workspace dependency

## Local Development

```powershell
# Use local PostgreSQL (auto-detects if K8s cluster is unreachable)
$env:DEV_INFRA_MODE='local'

# Start all services (PostgreSQL + API + Web)
powershell -ExecutionPolicy Bypass -File .\scripts\start.ps1

# Or Unix:
DEV_INFRA_MODE=local bash scripts/start.sh
```

## Build Order

```text
npm ci                # Install all workspace packages
npm run prisma:validate  # Validate Prisma schema
npm run db:generate   # Generate Prisma clients (all 9 services)
npm run typecheck:api    # Typecheck auth + API services
npm run typecheck:web    # Typecheck Next.js web
npm run build:all     # Build all services (API + auth + clinical + billing + product + queue + lab + cms + web)
```

## What NOT to Commit

- `dist/`, `.next/`, `node_modules/` - generated by `npm ci`
- Runtime logs in `apps/*/logs/`
- Local `.env` files - use repository `.env.example` instead
- `prisma/seed.ts` data with hard-coded IDs - use tenant slugs/natural keys

## Environment Variable Reference

| Variable | Description | Required |
|---|---|---|
| `DATABASE_URL` | PostgreSQL connection string | Yes |
| `NODE_ENV` | `development`/`staging`/`production` | Yes |
| `APP_ENV` | Alias for `NODE_ENV` | Yes |
| `DEFAULT_TENANT_SLUG` | Default tenant for local dev | Recommended |
| `TENANT_DEFAULT_PLAN` | Default tenant plan (STARTER/PRO/ENTERPRISE) | Recommended |
| `JWT_SECRET` | Signing key for access tokens | Yes |
| `JWT_EXPIRES_IN` | Access token TTL | Recommended |
| `REFRESH_TTL_DAYS` | Refresh token expiry | Recommended |
| `BCRYPT_SALT_ROUNDS` | Password hashing rounds | Recommended |

## Kubernetes Namespace Mapping

| `APP_ENV` | Namespace | Overlay Path |
|---|---|---|
| `development` | `cliniccare-development` | `infrastructure/k8s/overlays/development` |
| `staging` | `cliniccare-staging` | `infrastructure/k8s/overlays/staging` |
| `production` | `cliniccare-production` | `infrastructure/k8s/overlays/prod` |

**Do not use** the legacy generic `cliniccare` namespace for environment deployments.

## Multi-Tenant Data Isolation

- **Logical**: All records carry `organizationId` foreign key
- **Physical**: Production uses separate DB schemas/cluster; dev/staging share pooled instance
- **API**: `X-Tenant-Slug` header resolves tenant context; `X-Clinic-Id` narrows scope
- **RBAC**: `UserRole` and `RolePermission` are tenant-scoped or clinic-scoped
- **Seed**: Uses `SEED_TENANT_SLUG` environment variable; never hard-coded IDs

## Microservice-Specific Notes

### Auth Service

- Manages JWT issuance, refresh tokens, tenant signup
- Database: `organizations`, `users`, `refresh_tokens`, `role_permissions`
- K8s resources: ConfigMap for JWT secrets, Secret for bcrypt salts

### Clinical Service

- Manages patients, appointments, consultations, prescriptions
- Database: `patients`, `appointments`, `consultations`, `prescriptions`, `treatment_plans`
- K8s resources: Horizontal pod autoscaler, resource limits (CPU: 200m, Memory: 256Mi)

### Billing Service

- Manages orders, payments, invoices
- Database: `orders`, `payments`, `invoices`, `refunds`
- K8s resources: CPU: 100m, Memory: 128Mi (lower load)

### Product/Catalog Service

- Manages products, categories, inventory, orders
- Database: `products`, `product_categories`, `inventory_transactions`
- K8s resources: Resource limits (CPU: 150m, Memory: 192Mi)

### Queue Service

- Manages queue tickets, patient flow
- Database: `queue_tickets`
- K8s resources: Low resource (CPU: 50m, Memory: 64Mi)

### Lab/Reports Service

- Manages lab reports, test results
- Database: `lab_reports`
- K8s resources: CPU: 100m, Memory: 128Mi

### CMS/Engagement Service

- Manages CMS pages, notifications, engagement
- Database: `cms_pages`, `notification_templates`, `notifications`
- K8s resources: CPU: 100m, Memory: 128Mi

## Deployment Commands

```powershell
# Deploy all microservices to development namespace
kubectl apply -k infrastructure/k8s/overlays/development

# Deploy single service (e.g., auth only)
kubectl apply -k infrastructure/k8s/overlays/development --recursive -l app=auth

# Rollout restart specific service
kubectl rollout restart deployment auth-service -n cliniccare-development

# Check deployment status
kubectl get pods -n cliniccare-development -l app in (auth-service, api-service, web-service)
```
