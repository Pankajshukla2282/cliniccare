# Kubernetes manifests — ClinicCare Platform

No Docker Compose in this repo. All environments (including local dev on
docker-desktop) deploy to Kubernetes.

## Layout

```
infrastructure/k8s/
  base/          # every environment (namespace, postgres, redis, quota, api, web, HPA, ingress, PDB, backup)
    kustomization.yaml   # namespace + secretGenerator from repo-root .env
  overlays/
    prod/        # production: ghcr images (__IMAGE_TAG__ placeholder), 2x replicas, NODE_ENV=production
```

The prod overlay references `../../base`, so a single source of truth stays in
`base/` and per-environment tuning lives in `overlays/`.

## Deploy (docker-desktop / local)

Secrets are generated by Kustomize from the repo-root `.env` (gitignored).
Because the `.env` lives outside this tree, build with
`--load-restrictor LoadRestrictionsNone` before piping to `kubectl apply -f -`.
(Never use `kubectl apply -k` here — it refuses to read a file outside this dir.)

1. **Build the app images first** (the api image also ships Prisma CLI +
   `prisma/migrations` for the migrate initContainer):

```powershell
docker build -t cliniccare/api:dev -f apps/api/Dockerfile .
docker build -t cliniccare/web:dev -f apps/web/Dockerfile .
```

2. **Apply the base** (migrations run automatically on new api pods via the
   `migrate` initContainer):

```powershell
kubectl kustomize infrastructure/k8s/base --load-restrictor LoadRestrictionsNone | kubectl apply -f -
kubectl get pods -n cliniccare
```

3. Smoke test: `kubectl get ingress -n cliniccare`, then hit the healthz
   endpoints (`api` /healthz, `web` /healthz).

Rolling update with the same command; new pods run `prisma migrate deploy`
before serving. Verify with `kubectl rollout status deploy/api -n cliniccare`.

## Secrets

`api-secrets` and `postgres-credentials` are generated from the repo-root
`.env` (gitignored) via `secretGenerator` in `kustomization.yaml` — no YAML
here contains credentials. Edit root `.env` and re-apply; a pod restart picks
up new values. Keep real values out of VCS (use a secret manager for shared
environments — see `docs/runbook-cloud.md`).

## Hardening

- `12-quota.yaml` — ResourceQuota + LimitRange guardrails.
- `13-networkpolicy.yaml` — namespace segmentation (DNS + intra-namespace +
  external HTTPS egress for api/web; inbound only via ingress).
- `60-pdb.yaml` — PodDisruptionBudgets for api/web.
- `70-backup.yaml` — daily `pg_dump` CronJob onto a PVC (keeps 7 dumps).
- Probes: postgres (`pg_isready`), redis (`redis-cli ping`), api/web (`/healthz`).
